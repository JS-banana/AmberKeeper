# Context Snapshot — service-history-ux-round3

- Task statement: Refine the AmberKeeper desktop utility area so service management and history archive feel denser, cleaner, and more icon-first; add a manual refresh path for session visibility.
- Desired outcome: A shippable renderer + data-refresh update that removes unnecessary copy/URL clutter, adds a left-side utility nav, compresses the history archive header/list/detail density, and makes new sessions easier to surface.
- Known facts/evidence:
  - Utility navigation is currently a top pill nav inside the workbench in `apps/desktop/src/renderer/src/App.tsx:70-125` and styled in `apps/desktop/src/renderer/src/styles.css:308-366`.
  - Service management still shows explanatory copy, provider home URLs, and a text drag hint in `apps/desktop/src/renderer/src/pages/SettingsPage.tsx:54-169`.
  - The drag handle and icon action affordances are fixed at 34x34 and the drag hint reserves extra row height in `apps/desktop/src/renderer/src/styles.css:721-867`.
  - History archive still uses a tall sticky hero with “全部历史会话” copy, text provider tabs, and a text CTA in `apps/desktop/src/renderer/src/pages/LibraryPage.tsx:68-167` plus `styles.css:607-706`.
  - Session rows and detail header currently spend noticeable space on descriptive copy and secondary metadata in `ConversationList.tsx:12-49`, `ConversationMessagePane.tsx:69-180`, and `styles.css:1681-1795`.
  - Renderer session data only refreshes on first mount or after explicit provider/session mutations; runtime-status events only patch `runtimeStatus` without reloading sessions/messages in `workspace-store.ts:42-91` and `:235-246`.
  - Main process capture persistence sends runtime-status updates after capture attempts via `recordAttempt()` / `publishRuntimeStatus()` but not a dedicated session-refresh payload in `main/index.ts:541-557` and `:993-999`.
- Constraints:
  - Keep brownfield React/Electron patterns; no new dependencies.
  - Prefer icon-first actions with hover descriptions and accessible labels.
  - Avoid regressing drag reorder, enable/disable, export, delete, or diagnostics entry behavior.
- Unknowns/open questions:
  - Whether manual refresh alone is enough or whether runtime-status-driven auto refresh is also needed.
  - Whether provider export format remains a visible select or can be collapsed into an icon-triggered menu later.

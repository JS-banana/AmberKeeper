# Separate Chat Data Location From App Data Location

AmberKeeper lets users choose a **聊天数据位置** for retained conversation data without moving the whole Electron `userData` tree, so provider login state, browser cache, and bootstrap configuration can stay in the default app data directory. Location changes, including restoring the default location, require a verified migration and restart, with the current running app continuing to use the current chat store until migration runs at startup before the chat store is opened: copy the chat data artifacts first, open and validate the new copy, update the bootstrap pointer only after validation succeeds, and remove the old chat data files only after the new location is confirmed usable. Target folders that already contain AmberKeeper chat data are rejected instead of merged or overwritten. If the configured location is unavailable at startup, AmberKeeper must not silently fall back to the default location and create a new chat store; it should block chat-data writes until the user chooses a valid location or explicitly restores the default location.
